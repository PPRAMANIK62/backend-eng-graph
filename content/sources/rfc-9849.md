## Summary

Published in 2026. Defines Encrypted Client Hello (ECH): the client
encrypts its ClientHello, SNI included, under a public key the server
publishes, usually in DNS. It hides which server behind a shared front
you're reaching, but only if the other leaks (plain DNS, a dedicated IP
address) are closed too.

## Key claims

- What ECH is. "This document describes a mechanism in Transport Layer Security (TLS) for encrypting a ClientHello message under a server public key." (Abstract)
- Plaintext SNI is the biggest leak left in TLS 1.3. "The plaintext Server Name Indication (SNI) extension in ClientHello messages, which leaks the target domain for a given connection, is perhaps the most sensitive information left unencrypted in TLS 1.3." (1)
- ECH protects the SNI and the ALPN list. "This protects the SNI and other potentially sensitive fields, such as the Application-Layer Protocol Negotiation (ALPN) list" (1)
- ECH alone doesn't hide the server; DNS and IP addresses can still leak it. "ECH is not in itself sufficient to protect the identity of the server." (1)
- The server has to publish an ECH configuration for clients to use it. "A client-facing server enables ECH by publishing an ECH configuration, which is an encryption public key and associated metadata." (3.2)
