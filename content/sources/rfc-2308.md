## Summary

The 1998 spec that makes caching "this doesn't exist" answers
mandatory. It defines NXDOMAIN and NODATA responses, says the negative
TTL comes from the zone's SOA record, redefines the SOA MINIMUM field as
the negative-caching TTL, and allows caching server failures for up to
five minutes.

## Key claims

- Negative caching cuts response time and traffic, and is no longer optional. "With this in mind negative caching should no longer be seen as an optional part of a DNS resolver." (Abstract)
- A negative answer carries the zone's SOA in the authority section so it can be cached. "Name servers authoritative for a zone MUST include the SOA record of the zone in the authority section of the response when reporting an NXDOMAIN or indicating that no data of the requested type exists." (3)
- NODATA looks like success with an empty answer. "NODATA is indicated by an answer with the RCODE set to NOERROR and no relevant answers in the answer section." (2.2)
- The negative TTL is the smaller of the SOA's own TTL and its MINIMUM field. "The TTL of this record is set from the minimum of the MINIMUM field of the SOA record and the TTL of the SOA itself, and indicates how long a resolver may cache the negative answer." (3)
- The SOA MINIMUM field had three meanings over time; the negative TTL is now its only meaning. "The remaining of the current meanings, of being the TTL to be used for negative responses, is the new defined meaning of the SOA minimum field." (4)
- The $TTL directive in zone files sets the default TTL for records without one. (4)
- A cached negative answer counts down and must be dropped at zero. "upon reaching zero (0) indicates the cached negative answer MUST NOT be used again." (5)
- NXDOMAIN is cached per name (and class); NODATA per name, type and class. "A negative answer that resulted from a no data error (NODATA) should be cached such that it can be retrieved and returned in response to another query for the same <QNAME, QTYPE, QCLASS>" (5)
- Negative answers without an SOA shouldn't be cached. "Negative responses without SOA records SHOULD NOT be cached" (5)
- Server failures may be cached, for at most five minutes. "If it does so it MUST NOT cache it for longer than five (5) minutes" (7.1)
- A server can be considered dead after 120 seconds with no reply. "A server may be deemed to be dead or unreachable if it has not responded to an outstanding query within 120 seconds." (7.2)

## My notes

- The practical trap: if someone queries a name before you create it,
  the NXDOMAIN is cached for the negative TTL, so your new record looks
  missing for a while. That follows directly from sections 3 and 5.
