## Summary

LevelDB's built-in Bloom filter policy, about 90 lines. Picks the number
of probes from bits per key, sizes the bit array from the number of
keys, and generates the k probe positions from one 32-bit hash with
double hashing.

## Key claims

- Number of probes k is bits per key times about ln 2, rounded down, kept between 1 and 30. "k_ = static_cast<size_t>(bits_per_key * 0.69);  // 0.69 =~ ln(2)" (BloomFilterPolicy constructor)
- Rounded down on purpose. "We intentionally round down to reduce probing cost a little bit" (constructor)
- A minimum size stops tiny filters from being useless. "For small n, we can see a very high false positive rate.  Fix it by enforcing a minimum bloom filter length." (CreateFilter)
- One hash, many probes, by double hashing. "Use double-hashing to generate a sequence of hash values." (CreateFilter)
- k is stored in the filter, so filters built with other settings can still be read. "Use the encoded k so that we can read filters generated by bloom filters created using different parameters." (KeyMayMatch)
- A lookup stops at the first zero bit. "if ((array[bitpos / 8] & (1 << (bitpos % 8))) == 0) return false;" (KeyMayMatch)
