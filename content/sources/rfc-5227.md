## Summary

Updates RFC 826 with a way for a host to check that nobody else is
using its IPv4 address before and after taking it. Used here for its
security section on ARP and for what "gratuitous ARP" means.

## Key claims

- ARP has no protection against lying hosts. "A malicious host may send fraudulent ARP packets on the network, interfering with the correct operation of other hosts." (5, Security Considerations)
- One host can claim every address. "it is easy for a host to answer all ARP Requests with Replies giving its own hardware address, thereby claiming ownership of every address on the network." (5)
- What Stevens called "gratuitous ARP" is what this RFC calls an ARP Announcement. "What Stevens describes as Gratuitous ARP is the exact same packet that this document refers to by the more descriptive term 'ARP Announcement'." (4)
- Traditional gratuitous ARP is one announcement when an interface comes up, which doesn't detect conflicts. "This traditional Gratuitous ARP implementation sends only a single ARP Announcement when an interface is first configured." (4)
