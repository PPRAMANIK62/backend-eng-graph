## Summary

HTTP/3's header compression (2022). It keeps HPACK's static and dynamic
tables but moves table updates onto their own unidirectional stream, so
compressed headers on request streams can arrive in any order. The
encoder chooses how much blocking it risks for better compression.

## Key claims

- HPACK on QUIC would bring back head-of-line blocking. "If HPACK were used for HTTP/3 ([HTTP/3]), it would induce head-of-line blocking for field sections due to built-in assumptions of a total ordering across frames on all streams." (1)
- QPACK trades blocking against compression. "with flexibility for implementations to balance between resilience against head-of-line blocking and optimal compression ratio." (1)
- A header block can refer to a table entry that hasn't arrived yet. "a decoder might encounter a representation that references a dynamic table entry that it has not yet received." (2.1.2)
- Such a stream waits, "blocked". "the stream cannot be processed immediately and is considered "blocked"" (2.1.2)
- The decoder caps how many streams may block. "The decoder specifies an upper bound on the number of streams that can be blocked using the SETTINGS_QPACK_BLOCKED_STREAMS setting" (2.1.2)
- The encoder can avoid blocking entirely by using only acknowledged entries, at a cost in size. "An encoder can avoid the risk of blocking by only referencing dynamic table entries that have been acknowledged, but this could mean using literals." (2.1.2)

- QPACK keeps a static and a dynamic table, like HPACK. "Unlike in HPACK, entries in the QPACK static and dynamic tables are addressed separately." (3)
- Table changes travel on a separate one-way encoder stream. "An encoder stream is a unidirectional stream of type 0x02." (4.2) and "An encoder sends encoder instructions on the encoder stream to set the capacity of the dynamic table and add dynamic table entries." (4.3)
- Header blocks on request streams only refer to the tables. "These representations reference the static table or the dynamic table in a particular state, but they do not modify that state." (4.5)
