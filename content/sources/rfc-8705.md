## Summary

RFC 8705 (2020) binds OAuth access tokens to the client's TLS
certificate. The token carries a hash of the certificate; a resource
server accepts it only over a mutual-TLS connection made with that same
certificate.

## Key claims

- What it defines. "This document describes OAuth client authentication and certificate- bound access and refresh tokens using mutual Transport Layer Security (TLS) authentication with X.509 certificates." (Abstract)
- The certificate hash in the token. "The value of the "x5t#S256" member is a base64url-encoded [RFC4648] SHA-256 [SHS] hash" [inner quotes around x5t#S256] (3.1)
- Resource requests must use the same certificate. "those requests MUST be made over a mutually authenticated TLS connection using the same certificate that was used for mutual TLS at the token endpoint." (3)
- Mismatch means reject. "MUST verify that the certificate matches the certificate associated with the access token." (3)
- Rotating the certificate invalidates the tokens. "It also implies that access tokens are invalidated when a client updates the certificate" (6.3)
- TLS termination at a proxy is left out of scope. "How the client certificate metadata is securely communicated between the intermediary and the application server, in this case, is out of scope of this specification." (6.5)
