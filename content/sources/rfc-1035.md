## Summary

The 1987 companion to RFC 1034 with the wire details: size limits, the
record types and their data formats, the message layout (header,
question, answer, authority, additional), and how DNS runs over UDP and
TCP on port 53. Parts are updated by later RFCs (6891 for bigger UDP
messages, 7766 for TCP, 8767 for the TTL definition).

## Key claims

- Size limits: labels 63 octets, names 255 octets, UDP messages 512 octets. "UDP messages    512 octets or less" (2.3.4)
- Every resource record has the same layout: owner NAME, TYPE, CLASS, TTL, RDLENGTH, then the type-specific RDATA. "All RRs have the same top level format shown below:" (3.2.1)
- NS data is a host that should be authoritative for the domain. "A <domain-name> which specifies a host which should be authoritative for the specified class and domain." (3.3.11)
- A CNAME's data is the canonical name; the owner is the alias; name servers may restart the query at the canonical name. "CNAME RRs cause no additional section processing, but name servers may choose to restart the query at the canonical name in certain cases." (3.3.1)
- Record type numbers: A is 1, NS 2, CNAME 5, SOA 6, PTR 12, MX 15, TXT 16. "A               1 a host address" (3.2.2)
- NS names an authoritative name server. "NS              2 an authoritative name server" (3.2.2)
- CNAME points an alias at the canonical name. "CNAME           5 the canonical name for an alias" (3.2.2)
- SOA marks the start of a zone. "SOA             6 marks the start of a zone of authority" (3.2.2)
- MX data is a 16-bit preference plus a host; lower is preferred. "Lower values are preferred." (3.3.9)
- SOA fields: MNAME, RNAME, SERIAL, REFRESH, RETRY, EXPIRE, MINIMUM; SERIAL is the zone's version number. "The unsigned 32 bit version number of the original copy of the zone." (3.3.13)
- TXT holds text whose meaning depends on where it is. "TXT RRs are used to hold descriptive text.  The semantics of the text depends on the domain where it is found." (3.3.14)
- Reverse lookups live under IN-ADDR.ARPA with the address octets reversed. "Thus data for Internet address 10.2.0.52 is located at domain name 52.0.2.10.IN-ADDR.ARPA." (3.5)
- Every message has five sections: header, question, answer, authority, additional. "The top level format of message is divided into 5 sections" (4.1)
- The header's 16-bit ID matches replies to queries. "This identifier is copied the corresponding reply and can be used by the requester to match up replies to outstanding queries." (4.1.1)
- Header flags: AA (authoritative answer), TC (truncated), RD (recursion desired), RA (recursion available). "TC              TrunCation - specifies that this message was truncated due to length greater than that permitted on the transmission channel." (4.1.1)
- DNS uses port 53 over both UDP and TCP. "The Internet supports name server access using TCP [RFC-793] on server port 53 (decimal) as well as datagram access using UDP [RFC-768] on UDP port 53 (decimal)." (4.2)
- Over UDP, messages are capped at 512 bytes; longer ones are truncated with TC set. "Longer messages are truncated and the TC bit is set in the header." (4.2.1)
- UDP is the recommended way to send ordinary queries, and since packets can be lost the client must retransmit. "Queries sent using UDP may be lost, and hence a retransmission strategy is required." (4.2.1)
- Retransmission advice: try other servers first; minimum interval 2-5 seconds. "the minimum retransmission interval should be 2-5 seconds." (4.2.1)
- Over TCP each message is prefixed with a 2-byte length. "The message is prefixed with a two byte length field which gives the message length, excluding the two byte length field." (4.2.2)
- Zone transfers must use TCP. "Zone refresh activities must use virtual circuits because of the need for reliable transfer." (4.2)

Added for `dns-records` audit:

- The IN class is the Internet. "IN              1 the Internet" (3.2.4)
- Why reverse names are reversed: so a zone can be one network. "The reversal, though awkward to read, allows zones to be delegated which are exactly one network of address space." (3.5)

## My notes

- The 512-byte limit is lifted by EDNS (RFC 6891); the truncation and
  retry over TCP path is tightened by RFC 7766.
