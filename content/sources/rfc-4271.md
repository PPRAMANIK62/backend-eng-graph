## Summary

The BGP-4 standard: how autonomous systems exchange reachability over
TCP, the message types, path attributes, and the route selection
process. The rfc-editor.org info page lists 12 updating RFCs, including
RFC 6793 (four-octet AS numbers) and RFC 8212 (EBGP routes aren't
propagated without a configured policy).

## Key claims

- BGP is the routing protocol between autonomous systems. "The Border Gateway Protocol (BGP) is an inter-Autonomous System routing protocol." (1)
- It exchanges reachability, including the list of ASes a route has passed through, enough to prune loops and apply policy. "This information is sufficient for constructing a graph of AS connectivity for this reachability, from which routing loops may be pruned and, at the AS level, some policy decisions may be enforced." (1)
- BGP-4 carries CIDR prefixes and supports aggregation. "These mechanisms include support for advertising a set of destinations as an IP prefix and eliminating the concept of network \"class\" within BGP." (1)
- An AS is a set of routers under one technical administration that looks like one coherent routing plan from outside. "The classic definition of an Autonomous System is a set of routers under a single technical administration" (1.1)
- BGP runs over TCP port 179, so it doesn't implement its own retransmission. "BGP listens on TCP port 179." (2)
- After the initial table exchange, only changes are sent; no periodic refresh. "Incremental updates are sent as the routing tables change.  BGP does not require a periodic refresh of the routing table." (2)
- KEEPALIVEs keep the session known to be alive; errors send NOTIFICATION and close it. "KEEPALIVE messages may be sent periodically to ensure that the connection is live." (2)
- External peers are in another AS (EBGP), internal peers in the same one (IBGP). "Internal BGP and external BGP are commonly abbreviated as IBGP and EBGP." (2)
- AS_PATH lists the ASes an announcement has passed through. "This attribute identifies the autonomous systems through which routing information carried in this UPDATE message has passed." (5.1.2)
- Sending to an external peer, a speaker puts its own AS number at the front (leftmost) of the path; internal peers don't change it. "the local system prepends its own AS number as the last element of the sequence (put it in the leftmost position with respect to the position of octets in the protocol message)." (5.1.2 b)
- Loop detection: reject a route whose AS_PATH already contains your own AS. "checking that the autonomous system number of the local system does not appear in the AS path." (9.1.2)
- Route choice starts from a locally configured degree of preference (policy). "The higher degree of preference MUST be preferred." (5.1.5, LOCAL_PREF)
- The shortest AS_PATH is only a tie-breaker among equally preferred routes. "Remove from consideration all routes that are not tied for having the smallest number of AS numbers present in their AS_PATH attributes." (9.1.2.2 a)
- The security section only covers protecting the TCP session (MD5 per RFC 2385), not whether announcements are true. "A BGP implementation MUST support the authentication mechanism specified in RFC 2385 [RFC2385]." (Security Considerations)

Added 2026-09-28 (audit) for `bgp`:

- Running over TCP means BGP needs no retransmission of its own. "This eliminates the need to implement explicit update fragmentation, retransmission, acknowledgement, and sequencing." (2)
- The session starts with the routes the export policy allows, then only changes. "The initial data flow is the portion of the BGP routing table that is allowed by the export policy, called the Adj-Ribs-Out (see 3.2)." (2)
