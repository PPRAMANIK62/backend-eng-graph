## Summary

The SLSA v1.2 build track: levels L0 to L3, each defined by what the
provenance (the record of how an artifact was built) guarantees. L1
provenance exists, L2 it's signed by a hosted build platform, L3 the
platform is hardened so builds can't tamper with each other or reach
the signing key.

## Key claims

- The levels table: L1 "Provenance showing how the package was built", L2 "Signed provenance, generated by a hosted build platform", L3 "Hardened build platform". (table at top)
- Focus per level: L1 mistakes and documentation, L2 tampering after the build, L3 tampering during the build. (table at top)
- L1 provenance is easy to fake. "Can be used to prevent mistakes but is trivial to bypass or forge." (Build L1 summary)
- L1 provenance records who built it, how, and the top-level inputs. "what entity built the package, what build process they used, and what the top-level input to the build were." (Build L1 requirements)
- L2: the hosted platform signs the provenance and the consumer checks it. "Validate the authenticity of the provenance." (Build L2 requirements, Consumer)
- L2 stops tampering after the build. "Prevents tampering after the build through digital signatures" (Build L2 benefits)
- L3: runs can't influence each other, and user build steps can't reach the signing secret. "prevent secret material used to sign the provenance from being accessible to the user-defined build steps." (Build L3 requirements)
- L3 is for most releases but needs real platform changes. "Build L3 usually requires significant changes to existing build platforms." (Build L3 intended for)
- History: v1.0 dropped source requirements to focus on the build; v1.2 adds a Source track back. "In 1.2 the Source Track reintroduces coverage of source code." (note under the table)
