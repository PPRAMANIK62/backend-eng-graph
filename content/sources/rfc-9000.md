## Summary

The QUIC transport spec. Noted here only for how its streams avoid
head-of-line blocking across streams, and the limit of that.

## Key claims

- A loss blocks only the streams whose data was in the lost packet. "When a packet loss occurs, only streams with data in that packet are blocked waiting for a retransmission to be received, while other streams can continue making progress." (13)
- A packet carrying several streams blocks all of them when lost. "Note that when data from multiple streams is included in a single QUIC packet, loss of that packet blocks all those streams from making progress." (13)
- So implementations should put few streams in each packet. "Implementations are advised to include as few streams as necessary in outgoing packets without losing transmission efficiency to underfilled packets." (13)

Added 2026-09-28 for `head-of-line-blocking` audit:

- QUIC runs over UDP. "QUIC packets are carried in UDP datagrams [UDP] to better facilitate deployment in existing systems and networks." (Abstract)
- Each stream is its own ordered byte stream. "Streams in QUIC provide a lightweight, ordered byte-stream abstraction to an application." (2)
- Avoiding head-of-line blocking across streams is a stated goal. "One of the benefits of QUIC is avoidance of head-of-line blocking across multiple streams." (13)
