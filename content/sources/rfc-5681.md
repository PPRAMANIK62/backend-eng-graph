## Summary

The Standards Track description of TCP's four congestion control
algorithms: slow start, congestion avoidance, fast retransmit and fast
recovery (the "Reno" family). Also restart after idle and when to send
ACKs.

## Key claims

- The sender is limited by the smaller of the congestion window and the receiver's window. "The minimum of cwnd and rwnd governs data transmission." (3.1)
- cwnd is a sender-side limit; rwnd is the receiver-side limit. "The congestion window (cwnd) is a sender-side limit on the amount of data the sender can transmit into the network before receiving an acknowledgment (ACK), while the receiver's advertised window (rwnd) is a receiver-side limit on the amount of outstanding data." (3.1)
- These algorithms use loss as the congestion signal (ECN is the alternative). "the algorithms specified in this document work in terms of using loss as the signal of congestion." (3)
- Slow start probes an unknown network and starts the ACK clock. "Slow start additionally serves to start the \"ACK clock\" used by the TCP sender to release data into the network" (3.1)
- Slow start when cwnd < ssthresh, congestion avoidance when cwnd > ssthresh. (3.1)
- In slow start, cwnd grows by up to one SMSS per ACK of new data. "During slow start, a TCP increments cwnd by at most SMSS bytes for each ACK received that cumulatively acknowledges new data." (3.1)
- In congestion avoidance, about one segment per RTT. "During congestion avoidance, cwnd is incremented by roughly 1 full-sized segment per round-trip time (RTT)." (3.1)
- On loss, ssthresh drops to half the data in flight (at least 2 segments). "ssthresh = max (FlightSize / 2, 2*SMSS)" (3.1, equation 4)
- After a retransmission timeout cwnd drops to one segment and slow start begins again. "cwnd MUST be set to no more than the loss window, LW, which equals 1 full-sized segment (regardless of the value of IW)." (3.1)
- Three duplicate ACKs trigger fast retransmit. "The fast retransmit algorithm uses the arrival of 3 duplicate ACKs (as defined in section 2, without any intervening ACKs which move SND.UNA) as an indication that a segment has been lost." (3.2)
- Fast recovery skips slow start because duplicate ACKs show packets are still leaving the network. "the receipt of the duplicate ACKs not only indicates that a segment has been lost, but also that segments are most likely leaving the network" (3.2)
- Initial window upper bound is 2 to 4 segments depending on SMSS. (3.1, IW rules)
- After an idle period longer than one RTO, cwnd SHOULD drop back to the restart window. "a TCP SHOULD set cwnd to no more than RW before beginning transmission if the TCP has not sent data in an interval exceeding the retransmission timeout." (4.1)
- Delayed ACKs: ACK at least every second full-sized segment and within 500 ms. "an ACK SHOULD be generated for at least every second full-sized segment, and MUST be generated within 500 ms of the arrival of the first unacknowledged packet." (4.2)

Added for `congestion-control` audit:

- Why restart after idle: no ACKs to clock data out, and the path may have changed. "After an idle period, TCP cannot use the ACK clock to strobe new segments into the network, as all the ACKs have drained from the network." and "changing network conditions may have rendered TCP's notion of the available end-to-end network capacity between two endpoints, as estimated by cwnd, inaccurate" (4.1)
