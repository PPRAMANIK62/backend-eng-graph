## Summary

The protocol Let's Encrypt and other CAs use to issue certificates
without a human in the loop (2019). A client with an account key asks
for a certificate, proves control of the domain with a challenge
(HTTP file or DNS TXT record), and downloads the certificate.

## Key claims

- Web PKI certificates mostly authenticate domain names. "Certificates [RFC5280] in the Web PKI are most commonly used to authenticate domain names." (1)
- DV certificates only prove control of the domain, not who you are. "The only validation the CA is required to perform in the DV issuance process is to verify that the requester has effective control of the domain [CABFBR]." (1)
- DV is by far the most common kind. "\"Domain Validation\" (DV) certificates are by far the most common type." (1)
- Manual issuance took hours. "Informal usability tests by the authors indicate that webmasters often need 1-3 hours to obtain and install a certificate for a domain." (1)
- ACME automates issuance. "This document describes an extensible framework for automating the issuance and domain validation procedure, thereby allowing servers and infrastructure software to obtain certificates without user interaction." (1)
- After the challenges, the client finalizes the order with a CSR. "Once the client believes it has fulfilled the server's requirements, it should send a POST request to the order resource's finalize URL.  The POST body MUST include a CSR:" (7.4)
- HTTP challenge: put a file on the web server. "The ACME server challenges the client to provision a file at a specific path, with a specific string as its content." (8.3)
- The HTTP challenge runs over plain HTTP. "the challenge must be completed over HTTP, not HTTPS." (8.3)
- The path is fixed. "The path at which the resource is provisioned is comprised of the fixed prefix \"/.well-known/acme-challenge/\", followed by the \"token\" value in the challenge." (8.3)
- DNS challenge: publish a TXT record. "the client can prove control of that domain by provisioning a TXT resource record containing a designated value for a specific validation domain name." (8.4)
- The DNS record name starts with _acme-challenge. "prepending the label \"_acme-challenge\" to the domain name being validated" (8.4)
- The manual DV process: generate a CSR, paste it into the CA's web page, prove control (file on the web server, DNS record or email), download and install. "Cut and paste the CSR into a CA's web page." and "Download the issued certificate and install it on the user's Web Server." (1)
- The DNS challenge record holds a SHA-256 digest of the key authorization, built from the token and the account key. "A client fulfills this challenge by constructing a key authorization from the \"token\" value provided in the challenge and the client's account key.  The client then computes the SHA-256 digest [FIPS180-4] of the key authorization." (8.4)
