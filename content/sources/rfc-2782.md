## Summary

Defines the SRV record (type 33): for a named service and protocol under
a domain, it gives a list of target hosts and ports, with a priority
and a weight so clients can fail over and spread load.

## Key claims

- Format and type number. "Here is the format of the SRV RR, whose DNS type code is 33:" followed by "_Service._Proto.Name TTL Class SRV Priority Weight Port Target" (The format of the SRV RR)
- Service and protocol names get an underscore so they don't collide with real host labels. "An underscore (_) is prepended to the service identifier to avoid collisions with DNS labels that occur in nature." (Service)
- Example lookup name: `_ldap._tcp.example.com`. (Introductory example)
- Only use SRV where the protocol's spec says to. "Service SRV records SHOULD NOT be used in the absence of such specification." (Applicability Statement)
- Lowest priority number first. "A client MUST attempt to contact the target host with the lowest-numbered priority it can reach" (Priority)
- Weight spreads load among targets with the same priority. "Larger weights SHOULD be given a proportionately higher probability of being selected." (Weight)
- The record carries the port, so a service can run on any port. "This is often as specified in Assigned Numbers but need not be." (Port)
- The target must have address records and must not be an alias. "There MUST be one or more address records for this name, the name MUST NOT be an alias" (Target)
- A target of "." means no such service here. "A Target of "." means that the service is decidedly not available at this domain." (Target)
