## Summary

BCP for mobile and desktop apps using OAuth (2017): do the authorization
in the system browser, not an embedded web view; receive the redirect by
a private-use scheme, a claimed https URL, or a loopback port; use PKCE.

## Key claims

- Embedded web views let the host app copy credentials. "That approach has many drawbacks, including the host app being able to copy user credentials and cookies as well as the user needing to authenticate from scratch in each app." (1)
- The browser is safer and gives single sign-on. "Native app authorization requests that use the browser are more secure and can take advantage of the user's authentication state." (1)
- Embedded user-agents are forbidden. "native apps MUST NOT use embedded user-agents to perform authorization requests" (8.12)
- Desktop apps can receive the redirect on the loopback interface. "Native apps that are able to open a port on the loopback network interface without needing special permissions (typically, those on desktop operating systems) can use the loopback interface to receive the OAuth redirect." (7.3)
