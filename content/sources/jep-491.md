## Summary

Delivered in JDK 24. Lets a virtual thread that blocks inside a
`synchronized` method or block release its carrier platform thread,
removing the most common pinning case from JEP 444. A few pinning cases
remain (native code calling back into Java, class loading and
initialization).

## Key claims

- The change: virtual threads blocking in synchronized code release their platform threads. "arranging for virtual threads that block in such constructs to release their underlying platform threads for use by other virtual threads." (Summary)
- This removes nearly all pinning. "This will eliminate nearly all cases of virtual threads being pinned to platform threads" (Summary)
- Goal: existing libraries scale without rewriting synchronized. "Enable existing Java libraries to scale well with virtual threads without having to change them not to use synchronized methods and statements." (Goals)
- Native code that calls back into Java and blocks still pins. "if a virtual thread calls native code, either through a native method or the Foreign Function & Memory API, and that native code calls back to Java code that performs a blocking operation or blocks on a monitor, then the virtual thread will be pinned." (Description)
- Blocking in a class initializer still pins. "When blocking inside a class initializer." (remaining pinning cases)
