## Summary

What an IPv4 router must do. Used here for the forwarding algorithm, the
next-hop selection rules (basic match, then longest match), and TTL
handling.

## Key claims

- The spec writes out the forwarding algorithm because no earlier document did. "Since none of the primary protocol documents describe the forwarding algorithm in any detail, we present it here." (5.2.1)
- Real routers may implement it differently as long as the effect is the same; speed is the hard part. "Much of the challenge of writing router software is to maximize the rate at which the router can forward packets while still achieving the same effect of the algorithm." (5.2.1)
- Order: validate the header, then check local delivery, then look up the next hop. "A router MUST verify the IP header, as described in section [5.2.2], before performing any actions based on the contents of the header." (5.2.1)
- If the destination is on a directly attached network, the next hop is the destination itself; otherwise another router. "If so, the next hop address is the same as the IP Destination Address." (5.2.4.3)
- Next-hop selection starts with every route in the FIB and prunes. "Conceptually, any route lookup algorithm starts out with a set of candidate routes that consists of the entire contents of the FIB." (5.2.4.3)
- If nothing is left, the packet is dropped. "If the set ever becomes empty, the packet is discarded because the destination is unreachable." (5.2.4.3)
- Ties may be broken arbitrarily or by load-splitting. "the router may arbitrarily discard all but one of them, or may perform \"load-splitting\"" (5.2.4.3)
- Basic Match keeps routes whose prefix matches the destination; Longest Match then keeps the longest. Worked example: for 10.144.2.5, of 10.144.2.0/24, 10.144.0.0/16 and 10.0.0.0/8, "this rule would keep only the first (10.144.2.0/24) because its prefix length is longest." (5.2.4.3, rule 2)
- Every router must decrement TTL by at least one. "When a router forwards a packet, it MUST reduce the TTL by at least one." (5.3.1)
- At zero: discard and send ICMP Time Exceeded. "If the TTL is reduced to zero (or less), the packet MUST be discarded, and if the destination is not a multicast address the router MUST send an ICMP Time Exceeded message" (5.3.1)
- In practice TTL is a hop count. "the TTL is effectively a hop count limit on how far a datagram can propagate through the Internet." (5.3.1)
- The hop limit stops routing loops from melting the network. "Its hop count function is critical to ensuring that routing problems can't melt down the network by causing packets to loop infinitely in the network." (5.3.1, DISCUSSION)

Added (audit) for `ip-routing`:

- TTL is defined in seconds but works as a hop count. "It is an 8-bit field and the units are seconds." (5.3.1)
- An interior gateway protocol distributes routes inside one AS. "Interior Gateway Protocol A protocol that distributes routing information with an Autonomous System (AS)." (Glossary)
- OSPF and IS-IS are the link-state interior protocols it covers. "7.2.2 OPEN SHORTEST PATH FIRST - OSPF" and "7.2.3 INTERMEDIATE SYSTEM TO INTERMEDIATE SYSTEM - DUAL IS-IS" (7.2, section titles)
- The Basic Match example includes a non-matching 128.12.0.0/16. "this step would discard a route to net 128.12.0.0/16 but would retain any routes to the network prefixes 10.0.0.0/8 and 10.144.0.0/16, and any default routes." (5.2.4.3, rule 1)
