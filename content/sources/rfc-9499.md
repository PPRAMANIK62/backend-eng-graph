## Summary

The IETF's current glossary of DNS terms (BCP 219, March 2024, replacing
RFC 8499). It pins down words people use loosely: stub resolver,
recursive resolver, iterative mode, referral, authoritative server,
forwarder, TLD, zone cut, delegation, glue, NXDOMAIN and NODATA. Where
there's no agreement on a term, it says so.

## Key claims

- A stub resolver can't resolve on its own and leans on a recursive resolver. "A resolver that cannot perform all resolution itself." (6, Stub resolver)
- Iterative mode means answering with a referral. "A resolution mode of a server that receives DNS queries and responds with a referral to another server." (6, Iterative mode)
- Recursive mode means answering from cache or by querying other servers until there's a final answer. "either responds to those queries from a local cache or sends queries to other servers in order to get the final answers to the original queries." (6, Recursive mode)
- "Recursive server" and "recursive resolver" are used interchangeably. "both terms can be observed in use interchangeably." (6, Recursive mode)
- A recursive resolver is expected to cache. "In general, a recursive resolver is expected to cache the answers it receives" (6, Recursive resolver)
- In iterative resolution the client makes non-recursive queries and follows referrals itself. "the client repeatedly makes non-recursive queries and follows referrals and/or aliases." (6, Iterative resolution)
- A recursive resolver needs to know at least one root server address to start; this is priming, usually from a root hints file shipped with the software. "In order to operate in recursive mode, a resolver needs to know the address of at least one root server." (6, Priming)
- An authoritative server answers from its own copy of a zone and sets AA. "A server that knows the content of a DNS zone from local knowledge, and thus can answer queries about that zone without needing to query other servers." (6, Authoritative server, quoting RFC 2182)
- Referrals from authoritative servers have AA=0 and put the referral in the Authority (and Additional) sections. "these referrals have the AA bit set to 0 and come with referral data in the Authority and (if needed) the Additional sections." (6, Authoritative server)
- A referral says "ask over there". "provides the querying resolver with an alternative place to send its query." (4, Referrals)
- Forwarders today often sit between stubs and recursive servers. "In current use, however, forwarders often stand between stub resolvers and recursive servers." (6, Forwarder)
- Open (public) resolver: a full-service resolver that answers anyone. "A full-service resolver that accepts and processes queries from any (or nearly any) client." (6, Open resolver)
- An authoritative-only server serves only its zones and ignores requests for recursion. "A name server that only serves authoritative data and ignores requests for recursion." (6, Authoritative-only server)
- A TLD is a zone one level below the root, nothing special to the protocol. "There is nothing special, from the point of view of the DNS, about TLDs." (2, TLD)
- Delegation happens by adding NS records for the child in the parent zone. "Delegation happens when an NS RRset is added in the parent zone for the child origin." (7, Delegation)
- Glue: address records in the parent for name servers that live inside the child, needed to avoid a loop. "we could be faced with the situation where the NS RRs tell us that in order to learn a name server's address, we should contact the server using the address we wish to learn." (7, Glue records, quoting RFC 1034)
- NXDOMAIN: the name doesn't exist. NODATA: the name exists but has no records of that type, shown as NOERROR with an empty answer. "NODATA is indicated by an answer with the RCODE set to NOERROR and no relevant answers in the Answer section." (3, NODATA, quoting RFC 2308)
- The owner of a CNAME is the alias, not the canonical name. "the [owner] of a CNAME record is most certainly not a canonical name." (2, CNAME, quoting RFC 2181)
- Split DNS: different answers depending on who asks; not standardized. "Views are not a standardized part of the DNS, but they are widely implemented in server software." (6, View)

Added 2026-09-28 for `dns` audit:

- "Full resolver" has no agreed meaning. "This term is not properly defined in any RFC, and there is no consensus on what the term means." (6, Full resolver)
