## Summary

ICMP for IPv6. Same idea as ICMPv4 with a cleaner split between error
and informational messages, a dedicated Packet Too Big message, and a
rule that every node must rate-limit the errors it sends.

## Key claims

- Next Header 58 identifies ICMPv6. "Next Header value of 58." (1. Introduction)
- Error vs informational split by type number. "Thus, error messages have message types from 0 to 127; informational messages have message types from 128 to 255." (2.1)
- Types: 1 Destination Unreachable, 2 Packet Too Big, 3 Time Exceeded, 4 Parameter Problem; 128 Echo Request, 129 Echo Reply. (2.1)
- Routers must send Packet Too Big. "A Packet Too Big MUST be sent by a router in response to a packet that it cannot forward because the packet is larger than the MTU of the outgoing link." (3.2)
- Every node must rate-limit the errors it originates. "an IPv6 node MUST limit the rate of ICMPv6 error messages it originates." (2.4 (f))
- Token bucket recommended; a simple timer breaks bursty users like traceroute. "Rate-limiting mechanisms that cannot cope with bursty traffic (e.g., traceroute) are not recommended" (2.4 (f))
