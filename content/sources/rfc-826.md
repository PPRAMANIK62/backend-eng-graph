## Summary

The original ARP spec. Explains the problem (IP addresses are 32 bits,
Ethernet needs 48-bit addresses on the wire), the packet format, and
the request/reply algorithm. Updated by RFC 5227 and RFC 5494.

## Key claims

- The problem: the wire needs 48-bit Ethernet addresses, unrelated to protocol addresses. "the 10Mbit Ethernet requires 48.bit addresses on the physical cable, yet most protocol addresses are not 48.bits long, nor do they necessarily have any relationship to the 48.bit Ethernet address of the hardware." (The Problem)
- Ethernet lets many protocols share a cable through a type field in the header. "The 10Mbit Ethernet allows all of these protocols (and more) to coexist on a single cable by means of a type field in the Ethernet packet header." (The Problem)
- The Ethernet header is a 48-bit destination, a 48-bit source and a 16-bit type. "48.bit: Ethernet address of destination" (Packet format)
- The ARP packet carries hardware type, protocol type, address lengths, an opcode (request = 1, reply = 2), and sender and target hardware and protocol addresses. (Packet format; Definitions)
- Routing picks the next hop's protocol address first; ARP then turns it into a hardware address. "routing determines the protocol address of the next hop for the packet" (Packet Generation)
- On a cache miss, the packet may be dropped and a broadcast request sent. "it probably informs the caller that it is throwing the packet away (on the assumption the packet will be retransmitted by a higher network layer)" (Packet Generation)
- The request goes to every station. "It then causes this packet to be broadcast to all stations on the Ethernet cable" (Packet Generation)
- The target swaps fields and replies directly to the asker. "Send the packet to the (new) target hardware address on the same hardware on which the request was received." (Packet Reception)
- A receiver learns the sender's mapping before checking the opcode, since talk is usually two-way. "if A has some reason to talk to B, then B will probably have some reason to talk to A." (Packet Reception)
- A new mapping for a known address replaces the old one. "the new hardware address supersedes the old one." (Packet Reception)
- No periodic broadcasts; mappings are learned on demand. "Periodic broadcasting is definitely not desired." (Why is it done this way??)

Added 2026-09-28 (audit) for `ethernet-and-arp`:

- Periodic broadcasts would fill tables with unused entries, since most machines talk to only a few others. "The workstations aren't generally going to be talking to each other (and therefore have 100 useless entries in a table)" (Why is it done this way??)
