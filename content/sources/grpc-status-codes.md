## Summary

The list of gRPC's 17 status codes (0 to 16), what each means, which
ones the gRPC library itself produces and in which situations, and why
there's no universal list of codes to retry. Read from the master
branch when this was written.

## Key claims

- The codes run from OK (0) to UNAUTHENTICATED (16). (Table)
- Short meanings used: CANCELLED "typically by the caller"; INVALID_ARGUMENT "problematic regardless of the state of the system"; NOT_FOUND "Some requested entity (e.g., file or directory) was not found."; ABORTED "typically due to a concurrency issue such as a sequencer check failure or transaction abort"; UNIMPLEMENTED "not implemented or is not supported/enabled in this service"; UNAVAILABLE "most likely a transient condition, which can be corrected by retrying with a backoff". (Table)
- The library can produce the same code for different causes. "the gRPC library can generate the same status code for different cases." (Last paragraph)
- DEADLINE_EXCEEDED doesn't mean the work didn't happen. "For operations that change the state of the system, this error may be returned even if the operation has completed successfully." (Table, DEADLINE_EXCEEDED)
- UNAVAILABLE is usually transient, but retrying non-idempotent calls isn't always safe. "Note that it is not always safe to retry non-idempotent operations." (Table, UNAVAILABLE)
- Retry guidance: UNAVAILABLE retry the call, ABORTED retry at a higher level, FAILED_PRECONDITION don't retry until the state is fixed. "(a) Use `UNAVAILABLE` if the client can retry just the failing call." (Table, FAILED_PRECONDITION)
- INTERNAL means broken invariants and is reserved for serious errors. "This error code is reserved for serious errors." (Table, INTERNAL)
- Only some codes come from the library, so others must come from the application. "This allows applications to be sure that any other code it sees was actually returned by the application" (after the table)
- Library-generated cases include: deadline expires (DEADLINE_EXCEEDED), method not found (UNIMPLEMENTED), server shutting down (UNAVAILABLE), server app throws (UNKNOWN), message larger than the limit (RESOURCE_EXHAUSTED), keepalive watchdog times out (UNAVAILABLE). (Library-generated table)
- Seven codes are never generated by the library: INVALID_ARGUMENT, NOT_FOUND, ALREADY_EXISTS, FAILED_PRECONDITION, ABORTED, OUT_OF_RANGE, DATA_LOSS. (List)
- There's no fixed list of codes to retry on. "there is no fixed list of status codes on which it is appropriate to retry in all applications." (Last paragraph)

Added for `grpc` audit:

- ABORTED means restart the read-modify-write. "(b) Use `ABORTED` if the client should retry at a higher level (e.g., when a client-specified test-and-set fails, indicating the client should restart a read-modify-write sequence)." (Table, FAILED_PRECONDITION)
- INTERNAL means broken invariants. "This means that some invariants expected by the underlying system have been broken." (Table, INTERNAL)
