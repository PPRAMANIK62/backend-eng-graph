## Summary

The header compression format used by HTTP/2 (2015). Both sides keep a
table of header fields they've seen: a fixed static table of common
fields and a dynamic table filled by the encoder. A field already in a
table is sent as a small index; new ones are sent as literals, often
Huffman coded. It was designed after DEFLATE-based compression in SPDY
turned out to leak secrets (CRIME).

## Key claims

- Uncompressed HTTP/1.1 headers waste bandwidth across many requests. "the redundant header fields in these requests unnecessarily consume bandwidth, measurably increasing latency." (1)
- SPDY's DEFLATE compression was broken by CRIME. "However, that approach exposed a security risk as demonstrated by the CRIME (Compression Ratio Info-leak Made Easy) attack" (1)
- A field is sent either as a literal or as an index into a table. "In the encoded form, a header field is represented either literally or as a reference to a header field in one of the header field tables." (1.1)
- Literals can be Huffman coded. "Literal values are either encoded directly or use a static Huffman code." (1.1)
- Two tables: a fixed static one and a dynamic one the encoder fills. "The static table (see Section 2.3.1) is predefined and contains common header fields (most of them with an empty value)." (2.3)
- The dynamic table is first in, first out. "The dynamic table consists of a list of header fields maintained in first-in, first-out order." (2.3.2)
- Each direction has its own tables. "the request and response dynamic tables are separate." (2.2)
- The encoder decides what goes in the dynamic table, and its size is bounded. "The encoder decides how to update the dynamic table and as such can control how much memory is used by the dynamic table." (2.3.2)
- An entry's size counts name, value and 32 bytes of overhead. "The size of an entry is the sum of its name's length in octets (as defined in Section 5.2), its value's length in octets, and 32." (4.1)
- The static table has 61 entries, the last being www-authenticate. (Appendix A, table row 61)
- In the spec's example second request, :method GET, :scheme http, :path / and the :authority added by the first request are each one byte: `82 86 84 be`. (C.3.2)
- An attacker who controls some headers and sees the compressed length can test guesses. "If a guess is compressed into a shorter length, the attacker can observe the encoded length and infer that the guess was correct." (7.1)
- HPACK only lets a guess match a whole value, which slows the attack but doesn't stop it. "HPACK mitigates but does not completely prevent attacks modeled on CRIME [CRIME] by forcing a guess to match an entire header field value rather than individual characters." (7.1.1)
- Low-entropy values stay at risk. "However, values with low entropy remain vulnerable." (7.1.1)
- The risk appears when a connection carries requests from parties that don't trust each other, e.g. a proxy merging clients. "sends requests from multiple clients on a single connection toward an origin server" (7.1.1)

- In the example, index 2 is `:method: GET` and index 4 is `:path: /` in the static table. (C.3.2 decoding, Appendix A)
- Never-indexed literals keep a field out of the dynamic table. "A literal header field never-indexed representation results in appending a header field to the decoded header list without altering the dynamic table." (6.2.3)
- Sensitive fields can be protected this way. "Implementations can also choose to protect sensitive header fields by not compressing them and instead encoding their value as literals." (7.1.3)
