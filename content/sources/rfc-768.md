## Summary

The whole UDP specification, three pages long, from August 1980. It
defines an 8-byte header on top of IP and nothing else: no connection,
no delivery guarantee, no duplicate protection. Still the current
standard.

## Key claims

- UDP sends messages with as little protocol as possible, and doesn't guarantee delivery. "This protocol provides a procedure for application programs to send messages to other programs with a minimum of protocol mechanism." (Introduction)
- No delivery or duplicate protection; use TCP if you need ordered reliable streams. "The protocol is transaction oriented, and delivery and duplicate protection are not guaranteed." (Introduction)
- The header is four 16-bit fields: source port, destination port, length, checksum. (Format, "User Datagram Header Format")
- The source port is optional and is where replies go. "If not used, a value of zero is inserted." (Fields, Source Port)
- Length counts header plus data, so it is at least 8. "(This means the minimum value of the length is eight.)" (Fields, Length)
- The checksum covers a pseudo-header with the IP addresses, protocol and length, like TCP's. "This checksum procedure is the same as is used in TCP." (Fields, Checksum)
- The pseudo-header protects against misrouted datagrams. "This information gives protection against misrouted datagrams." (Fields, Checksum)
- An all-zero checksum means the sender didn't compute one. "An all zero transmitted checksum value means that the transmitter generated no checksum (for debugging or for higher level protocols that don't care)." (Fields, Checksum)
- UDP is IP protocol 17. "This is protocol 17 (21 octal) when used in the Internet Protocol." (Protocol Number)
- The first users were the name server and TFTP. "The major uses of this protocol is the Internet Name Server [3], and the Trivial File Transfer [4]." (Protocol Application)
