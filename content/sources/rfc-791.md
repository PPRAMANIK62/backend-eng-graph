## Summary

The IPv4 specification. For this project mostly the header fields and
the fragmentation procedure: identification, flags (DF, MF), fragment
offset, and reassembly at the destination.

## Key claims

- Fragmentation exists because networks differ in packet size. "Fragmentation of an internet datagram is necessary when it originates in a local net that allows a large packet size and must traverse a local net that limits packets to a smaller size to reach its destination." (2.3, Fragmentation)
- A don't-fragment packet that doesn't fit is dropped. "If internet datagram marked don't fragment cannot be delivered to its destination without fragmenting it, it is to be discarded instead." (2.3)
- Receivers group fragments by the identification field and place them by offset. "The receiver of the fragments uses the identification field to ensure that fragments of different datagrams are not mixed." (2.3)
- The more-fragments flag marks all but the last fragment. "The more-fragments flag indicates (by being reset) the last fragment." (2.3)
- Reassembly keys on four fields. "combines internet datagrams that all have the same value for the four fields: identification, source, destination, and protocol." (2.3)
- Offset is counted in 8-byte units. "The fragment offset is measured in units of 8 octets (64 bits)." (3.1, Fragment Offset)
- The header length is counted in 32-bit words, minimum 5, so the smallest header is 20 bytes (up to 60 with options). "Note that the minimum value for a correct header is 5." (3.1, IHL)
- Identification is 16 bits; flags: "Bit 1: (DF) 0 = May Fragment,  1 = Don't Fragment." (3.1, Flags)
- Minimums. "Every internet module must be able to forward a datagram of 68 octets without further fragmentation." and "Every internet destination must be able to receive a datagram of 576 octets either in one piece or in fragments to be reassembled." (3.2)

Added for `ip-addressing` and `ip-routing` (rfc-editor.org info page: updated by RFC 1349, 2474 and 6864):

- Names, addresses and routes are different things. "A name indicates what we seek.  An address indicates where it is.  A route indicates how to get there." (2.3, Addressing)
- IP does two jobs. "The internet protocol implements two basic functions:  addressing and fragmentation." (1.4)
- "The selection of a path for transmission is called routing." (1.4)
- Addresses are 32 bits: a network part then a local part. "Addresses are fixed length of four octets (32 bits).  An address begins with a network number, followed by local address" (2.3)
- The 1981 split was by class: class a has 7 network bits and 24 local bits, class b 14 and 16, class c 21 and 8. (2.3, Addressing)
- A host can have several interfaces, each with several addresses. "provision must be made for a host to have several physical interfaces to the network with each having several logical internet addresses." (2.3)
- Header length is in 32-bit words, minimum 5 (20 bytes). "Note that the minimum value for a correct header is 5." (3.1, IHL)
- TTL is set by the sender and reduced along the path; at zero the datagram is destroyed. "If the time to live reaches zero before the internet datagram reaches its destination, the internet datagram is destroyed." (1.4)
- TTL is nominally in seconds but every hop takes at least one off. "every module that processes a datagram must decrease the TTL by at least one even if it process the datagram in less than a second" (3.1, Time to Live)

Added (audit) for `mtu-and-fragmentation`:

- Fragmentation can happen at gateways; reassembly only at the destination. "provides for the fragmentation of datagrams at gateways, with reassembly taking place at the destination internet protocol module in the destination host." (1.4)
