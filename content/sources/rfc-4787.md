## Summary

Best Current Practice 127: the vocabulary for how NATs behave with UDP,
split into mapping (which public port you get) and filtering (who may
send packets back in). Replaces the old "cone / symmetric" names.

## Key claims

- The old STUN terms were confusing. "Unfortunately, this terminology has been the source of much confusion, as it has proven inadequate at describing real-life NAT behavior." (3. Terminology)
- Endpoint-independent mapping: same public port for one internal address:port, whatever the destination. "The NAT reuses the port mapping for subsequent packets sent from the same internal IP address and port (X:x) to any external IP address and port." (4.1)
- Mapping choice doesn't change security; filtering does. "The security properties are fully determined by which packets the NAT allows in and which it does not." (4.1)
- Endpoint-independent mapping is required. "REQ-1: A NAT MUST have an "Endpoint-Independent Mapping" behavior." (4.1)
- Address-dependent filtering: to hear from a host, you must have sent to it first. "for receiving packets from a specific external endpoint, it is necessary for the internal endpoint to send packets first to that specific external endpoint's IP address." (5. Filtering Behavior)
- UDP mapping timer. "REQ-5: A NAT UDP mapping timer MUST NOT expire in less than two minutes" and "A default value of five minutes or more for the NAT UDP mapping timer is RECOMMENDED." (4.3)
- Hairpinning is required. "REQ-9: A NAT MUST support "Hairpinning"." (6)

Added (audit) for `nat`:

- Endpoint-independent filtering lets anyone reach a mapping once it exists. "The NAT filters out only packets not destined to the internal address and port X:x, regardless of the external IP address and port source (Z:z)." (5)
