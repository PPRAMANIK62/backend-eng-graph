## Summary

Defines HMAC (1997): a message authentication code built from any
iterated cryptographic hash and a secret key, computed as two nested
hashes with the key mixed in differently each time. Covers keys and
security.

## Key claims

- A MAC is an integrity check based on a secret key, shared by two parties. "Typically, message authentication codes are used between two parties that share a secret key in order to validate information transmitted between these parties." (1)
- HMAC works with any iterated hash and lets you swap the hash. "To allow for easy replaceability of the underlying hash function in case that faster or more secure hash functions are found or required." (1)
- The hash is assumed to work block by block with a compression function. "We assume H to be a cryptographic hash function where data is hashed by iterating a basic compression function on blocks of data." (2)
- The definition. "H(K XOR opad, H(K XOR ipad, text))" (2)
- ipad and opad constants. "ipad = the byte 0x36 repeated B times" and "opad = the byte 0x5C repeated B times." (2)
- Keys longer than the block are hashed first; keys shorter than the output are discouraged. "Applications that use keys longer than B bytes will first hash the key using H and then use the resultant L byte string as the actual key to HMAC." and "less than L bytes is strongly discouraged as it would decrease the security strength of the function." (2, 3)
- Keys longer than the output add little. "Keys longer than L bytes are acceptable but the extra length would not significantly increase the function strength." (3)
- Short keys are padded with zeros to the block size. "append zeros to the end of K to create a B byte string" (2)
- Keys must be random and refreshed. "Keys need to be chosen at random (or using a cryptographically strong pseudo-random generator seeded with a random seed), and periodically refreshed." (3)
- Breaking a MAC later doesn't expose past messages, unlike encryption. "A published breaking of a message authentication scheme would lead to the replacement of that scheme, but would have no adversarial effect on information authenticated in the past." (6)
- MD5's collision weakness didn't break HMAC-MD5 (as of 1997). "This attack and other currently known weaknesses of MD5 do not compromise the use of MD5 within HMAC as specified in this document" (1)

## My notes

- RFC 2104 names MD5 and SHA-1 as the common hashes; today it's HMAC-SHA256.
