## Summary

The current HTTP/2 spec, obsoleting RFC 7540. Its introduction names
two kinds of head-of-line blocking: HTTP/1.1's at the application
layer, which HTTP/2 fixes, and TCP's, which it doesn't.

## Key claims

- HTTP/1.1 pipelining still has application-layer HOL blocking, so clients open several connections. "HTTP/1.1 [HTTP/1.1] added request pipelining, but this only partially addressed request concurrency and still suffers from application-layer head-of-line blocking." (1)
- HTTP/2 doesn't fix TCP's HOL blocking. "Note, however, that TCP head-of-line blocking is not addressed by this protocol." (1)

Added 2026-09-28 for `head-of-line-blocking` audit:

- HTTP/2 interleaves messages on one connection. "Specifically, it allows interleaving of messages on the same connection and uses an efficient coding for HTTP fields." (1)
- Because of pipelining's limits, HTTP/1.x clients open several connections. "Therefore, HTTP/1.0 and HTTP/1.1 clients use multiple connections to a server to make concurrent requests." (1)
